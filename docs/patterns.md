# 时序组合发现方法说明

本服务在 `GET /pattern-report` 与 `POST /pattern-reports` 中提供冷链事件的时序组合发现。本文档说明口径与统计方法，使模式筛选、最小支持和多重比较的取舍留有依据。报告是关联筛查工具：匹配到的序列与退货的关联不等于致损原因，调度员应结合匹配记录中的真实事件与时间边界核对流程。

## 模式语义

模式是若干**步**的序列，每步是环节名的集合：

- 单名步（如 `中转`）匹配该环节的一个发生时刻；
- 双名步（如 `换箱∥装车`）匹配**同一发生时刻**出现的两个环节，对应两台扫描器的并行扫描；相同发生时刻不声明内部先后，因此并行步内不排序；
- 相邻步要求发生时刻**严格更晚**，且间隔不超过 `max_gap_hours`（闭区间）。同一环节重复出现（如 `中转 → 中转`）按不同的真实事件匹配，不按环节名去重。

一次**出现**由各步的时间锚点唯一确定。同一时刻同一环节被两台扫描器各扫一次时，只计一次出现，但匹配记录会列出全部事件 ID。每个模式分别报告：

- `occurrences`：出现次数（时间锚点组合数）；
- `shipments`：涉及货批数（货批去重）。

两者分列：一个货批内同一组合出现多次会推高出现次数，但不增加涉及货批数。

## 时点口径：什么算“事前线索”

事件按发生时刻排序参与匹配，但只有在 `decision_at`（计划使用流程信息的时点）**之前发生且已接收**（`received_at <= decision_at`）的事件才进入候选。迟到补传、退货之后才补做的检查，即使发生时刻较早，也不构成事前线索，在 `shipment_roles` 的 `late_received` 中单独计数。发生在前置区间 ` [start_at, min(end_at, decision_at))` 之外的事件计入 `outside_window`，同样不参与。

## 观察窗与货批角色

前置观察机会由业务历程（`start_at` 至 `min(end_at, decision_at)`）定义，不由退货结果倒推。观察窗完整覆盖该区间且无采集缺口相交的货批记为**完整**，否则记为**部分**并给出原因（起点未覆盖、终点未覆盖、缺口相交、无观察窗记录）。

角色决定货批在统计中的位置：

- **完整货批**：匹配到计为“出现”，未匹配可计为“未出现”，进入对照表（2×2）与暴露调整比较；
- **部分货批**：匹配到仍计为确定的“出现”（事件是真实记录），但未匹配**不能**视为“未出现”——缺口内不能声称某事件没有发生。因此部分货批不进入对照表，只在 `partial_role` 中单独描述（数量、匹配数、其中退货数）。发现阶段的最小支持同样区分 `complete_shipments` 与 `partial_shipments`。

跨采集缺口的匹配仍然有效（两端事件真实），但标记 `crosses_gap`，提示缺口内可能有未采集的中间事件。

## 两阶段设计与多重比较

1. **发现**：按 `start_at` 升序取较早 `discovery_fraction` 的货批为发现集，其余为验证集。发现阶段只做频繁模式挖掘（Apriori，步数上限 `max_length`，间隔上限 `max_gap_hours`），**不使用退货结果**。达到 `min_support`（发现集内涉及货批数）的模式进入验证，其余计数于 `rejected_by_support`。
2. **验证**：在较晚货批上评估每个候选与退货的关联及不确定性：
   - 货批级：完整货批的 2×2 表、退货率差与风险比（对数法置信区间）、Fisher 精确检验；
   - 暴露调整：以可观察前置小时为分母的出现率，条件二项法（精确泊松）给出率比置信区间。历程长、事件多的货批观察机会多，单看“是否出现”易受暴露影响，率比以时间为分母，避免长运输记录仅因事件多而被判高风险；两组的暴露小时中位数一并报告，便于核对暴露是否均衡；
   - 多重比较：对进入验证阶段的全部模式的 Fisher 检验按 `correction` 校正——`bh`（Benjamini-Hochberg，默认，报告 `q_value`）、`bonferroni`（报告 `adjusted_p`）或 `none`。检验数随参数变化，记录于 `multiple_testing.tests`。暴露调整的泊松检验为次要指标，未另行校正。

## 参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `min_support` | 8 | 发现阶段最小涉及货批数（1–1000） |
| `max_length` | 3 | 模式最大步数（1–4） |
| `max_gap_hours` | 24 | 相邻步最大间隔小时，闭区间（(0, 720]） |
| `discovery_fraction` | 0.5 | 发现集货批占比（[0.1, 0.9]） |
| `alpha` | 0.05 | 置信区间与多重比较水准（(0, 0.5)） |
| `correction` | bh | 多重比较方法：`bh` / `bonferroni` / `none` |

参数原样记录在每份报告的 `parameters` 中；保存的研究记录同时固化完整资料副本与全部匹配明细，内容校验保证不可更改。

## 匹配记录

每个模式的 `matches` 按发现/验证集分别列出每次出现：货批、完整性角色、各步发生时刻与真实事件 ID、起止时刻、跨度小时、是否跨采集缺口。调度员可据此回到原始扫描记录核对流程。再次强调：这些是**与退货统计相关**的序列，不是已确认的致损原因。
